## 2. Database (Supabase)

### Option A: revert only this release's functions (recommended)

`supabase/rollback/20261030000000_fix_broken_live_functions.down.sql` holds the
exact live definitions captured right before the migration was applied. It also
drops the two functions the release added and unschedules the
`assessment-expiry-sweep` cron job. It touches no table data. It was verified
round-trip (apply → rollback → all 433 function definitions and ACLs
byte-identical).

```bash
psql "host=aws-1-ap-northeast-2.pooler.supabase.com port=5432 user=postgres.ysitzlbjoueorndmnmdf dbname=postgres sslmode=require" \
  -v ON_ERROR_STOP=1 -f supabase/rollback/20261030000000_fix_broken_live_functions.down.sql
```

The file is one transaction, so it applies fully or not at all.

Note: rolling back re-breaks the fixed features. Submissions graded by the new
expiry sweep keep their scores; the rollback does not un-grade them.

### Option B: full snapshot restore (last resort)

`backups/20261030-pre-bugfix/` (local only, gitignored: contains user data and auth
hashes) has a `pg_dump` taken before any change:

- `full_public_auth_storage.dump`: custom-format dump of the `public`, `auth`, and
  `storage` schemas, schema + data
- `public_schema.sql`: readable schema-only dump of `public`

This **overwrites data written after the snapshot**. To restore only the `public` schema:

```bash
pg_restore --clean --if-exists --no-owner -n public \
  -d "host=aws-1-ap-northeast-2.pooler.supabase.com port=5432 user=postgres.ysitzlbjoueorndmnmdf dbname=postgres sslmode=require" \
  backups/20261030-pre-bugfix/full_public_auth_storage.dump
```
